# ТЗ: M-Vave SMC-PAD Bridge → версия 1.0.0

Исполнитель — новый агент без контекста прошлых сессий. Всё нужное — здесь и в файлах, на которые ссылки.

## 0. Контекст и правила работы

**Что это.** Windows-приложение: мост от BLE MIDI-контроллера M-Vave SMC-PAD к действиям на ПК.
- Python 3.13, Tk + CustomTkinter 6.
- Вход — `midi_gui.py`, пакет — `mvave/`.
- Текущая версия 0.3.0 (см. `CHANGELOG.md`). Репозиторий публичный: `github.com/eivl10/mvave-smc-pad`.

**Прочитать до начала:**
- `README.md` — что умеет программа, структура.
- `FIXES.md` — история багов и решений. Искать по имени файла или функции, целиком не читать. Особенно важны записи:
  - «новая вёрстка на CustomTkinter» — три ловушки CTk;
  - «смена темы падала на .!ctkframe»;
  - «свои окна вместо messagebox»;
  - «порядок блоков инспектора»;
  - «эмодзи в Tkinter не рисуются»;
  - «запись клавиши срабатывала со второго раза».
- `docs/PROTOCOL.md` §1 — какие кнопки молчат, что шлют банки.
- `mvave/theme.py` — палитры. `mvave/dialogs.py` — свои окна, кнопки, поля, меню.

**Обязательные правила:**
1. **Спека до кода.** Перед реализацией — план владельцу на согласование. Дизайн согласовывается картинкой: снимки окна в **обеих** темах (пример — скрипт снимков ниже) отправляются владельцу **до** коммита. «Тесты зелёные» — не приёмка дизайна.
2. **Тесты:**
   - `python tests/smoke_ui.py` (под `PYTHONIOENCODING=utf-8`, иначе падает на печати);
   - `python tests/test_config.py`;
   - `python tests/test_protocol.py`.
   
   Всё должно быть зелёным. На каждую новую функцию — проверка в `smoke_ui.py`. Прогон работает на временной копии конфига, боевой не трогает.
3. **Боевые данные владельца не трогать.**
   - `midi_config.json` в корне проекта и в `release/`, а также `release/_new/` — это живые настройки и пресеты. Сейчас владелец работает из `release/_new/SMC-PAD.exe`.
   - Копировать, переносить или перезаписывать — только с его «да» и после бэкапа, который проверен на диске.
4. **Сборка exe:** `python tools/build_exe.py [папка]`. Если `release/SMC-PAD.exe` запущен, файл занят. Тогда собирать в `release/_new` и менять после выхода владельца из программы через трей. Процесс владельца не убивать.
5. **Значки** — только глифы Segoe MDL2 Assets, в исходниках экранированы `\uXXXX`. Символы частной области в редакторе невидимы, а Edit-инструмент пишет их как есть. После правок проверить, что в `.py` нет байтов U+E000–U+F8FF. Эмодзи и символы вне BMP запрещены.
6. **Цвета** — только токены `theme.*`, прочитанные в момент создания виджета. Значения по умолчанию в сигнатурах не использовать: они застывают на теме, активной при импорте.
7. **CTk-ловушки:**
   - `.config()` у CTk-виджета уходит во внутреннюю рамку, поэтому для CTk — `.configure()`;
   - шрифты CTk в пикселях (`theme.C_*`), Tk — в пунктах (`theme.F_*`);
   - `textvariable` отключает плейсхолдер у CTkEntry;
   - CTk подменяет `configure` у tk-родителя (см. `rebuild_ui`).
8. **Git:**
   - коммиты по шагам, сообщение двуязычное: `type: English / по-русски`;
   - **без строк соавторства ИИ**;
   - перед push:
     - `git grep` по личным меткам (имя пользователя Windows, MAC контроллера, путь к рабочей папке владельца) — должно быть пусто;
     - `bash ~/.claude/skills/git-ship/scripts/prepush-scan.sh` → «чисто»;
   - push: `git -c credential.helper= -c credential.helper='!gh auth git-credential' push`;
   - `midi_config.json`, `HANDOFF.md`, `_backup/`, `presets/`, `release/` в git не попадают;
   - публикация в GitHub Releases — только по отдельному «да» владельца.
9. **FIXES.md:**
   - запись после каждого исправленного бага;
   - запись после каждого неочевидного решения, у которого был реальный выбор;
   - формат — как у существующих записей, до 6 строк.
10. **Heredoc** для многострочного кода не использовать: скрипты писать файлом, запускать отдельной командой.

**Снимки для владельца.** Шаблон — скрипт, который создаёт `App` на копии конфига, открывает окна через `root.after(...)` и снимает `ImageGrab` по `GetWindowRect`.
- Модальные окна блокируют `wait_window`: снимок и закрытие планируются через `after` до открытия окна.
- Снимать тёмную и светлую тему.

## 1. Галка «Запускать вместе с Windows»

- Где: меню «Настройки», отдельная строка-переключатель (CTkSwitch) над блоком «Тема».
- Механизм: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение `M-Vave SMC-PAD`.
  - Для exe — `"<путь к exe>" --tray`.
  - Из исходников — `"<pythonw.exe>" "<midi_gui.py>" --tray`.
  - Реестр, а не ярлык в «Автозагрузке»: `mvave/autostart.py` работает через `win32com`, а в exe pywin32 не собирается. Модуль переписать под реестр (`winreg`), старый ярлык в Startup-папке, если найден, — удалить с подтверждением владельца.
  - Путь к папке Startup — через `SHGetKnownFolderPath` (ctypes) или `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`, не через `win32com` (`_shell_folder`): в exe его нет. `create_desktop_shortcut` в exe сломан по той же причине — чинить (ответ владельца): ярлык создаётся без pywin32, цель — сам exe.
- Состояние галки читается из реестра при каждом открытии меню.
  - Если в реестре записан другой путь (exe переехал), галка показывается выключенной, в подсказке — «записан другой путь».
  - При включении путь перезаписывается.
- `--tray`: окно стартует свёрнутым в трей, BLE подключается как обычно.
  - Если значок трея не поднялся — окно показать. Иначе программа висит невидимой и её не закрыть (FIXES «tray.py — окно живёт в трее»).
- Проверка: включить → значение в реестре есть и путь верный; выключить → значения нет. Smoke-тест работает на подменённом ключе, боевой реестр не трогает.

## 2. Нижняя надпись обрезается — высота окна

Симптом: на снимке владельца «Сбросить все назначения» срезана по нижнему краю. Окно 1320×780, масштаб Windows, скорее всего, 125%.
- Минимальная и стартовая высота считаются от `winfo_reqheight()` собранного окна, а не заданы числом.
- Стартовая высота ограничена 90% рабочей области экрана (правило из AGY-sub). Если контент не влезает, скроллится список действий, а не окно.
- Запоминать размер и положение окна в конфиге (ключ программы — добавить в `appconfig._APP_KEYS`, чтобы пресеты его не переносили). При старте проверять, что окно попадает на существующий монитор.
  - Сохранять только когда окно в состоянии `normal`: у свёрнутого координаты `-32000`, у спрятанного в трей (`withdraw`) — мусор.
- Приёмка: снимки при масштабе 100%, 125%, 150% (менять `tk scaling` или реальную настройку): ничего не срезано, нижняя кромка кнопок видна целиком.

## 3. Замок «влево / вправо»: одно действие вместо двух

Сейчас в режиме «Влево / вправо» каждую сторону настраивают отдельно, хотя обычно это одна регулировка в две стороны.
- Между строками «◀ Влево» и «Вправо ▶» — значок замка (MDL2: `\uE72E` закрыт, `\uE785` открыт), кнопка-иконка.
- **Замок закрыт (по умолчанию):**
  - выбор действия на любой стороне ставит на другую противоположное;
  - если у действия есть параметр — поле одно на пару, но значение хранится **в каждой стороне** (`side["param"]`) и копируется в обе при правке. Общее поле на крутилку не заводить: так уже было, стороны затирали параметр друг другу (FIXES «_side — сторона крутилки должна быть словарём»).
- Действие без пары: замок сам открывается, под строками короткая подсказка «У этого действия нет пары — второе направление настраивается отдельно».
- **Замок открыт:** как сейчас, стороны независимы.
- Хранение: `binding["pair_lock"]` (bool).
  - Старые конфиги без ключа: замок закрыт, только если стороны уже противоположны друг другу. Иначе открыт — чужую настройку не перезаписывать.
- Таблица пар — в `mvave/actions.py`, словарь `OPPOSITE`, симметричный:

| Действие | Противоположное |
|---|---|
| `media.next_track` | `media.prev_track` |
| `media.volume_up` | `media.volume_down` |
| `window.snap_left` | `window.snap_right` |
| `window.monitor_left` | `window.monitor_right` |
| `window.maximize` | `window.minimize` |
| `desktop.left` | `desktop.right` |
| `browser.next_tab` | `browser.prev_tab` |
| `browser.back` | `browser.forward` |
| `browser.zoom_in` | `browser.zoom_out` |
| `edit.undo` | `edit.redo` |
| `pads.brightness_up` | `pads.brightness_down` |
| `monitor.brightness_up` | `monitor.brightness_down` |

- Агент сверяет таблицу с реестром действий и добавляет найденные пары. Список показать владельцу.
- Какая сторона «правая» по умолчанию: вправо (по часовой) — «вперёд / больше / вверх». Замок только зеркалит выбор и стороны не переставляет: если владелец поставил `media.next_track` слева, справа будет `media.prev_track`.
- Замок и подсказка вставляются между строками сторон через `pack(before=...)` — целью должен быть **сосед** в том же контейнере, не родитель. Ровно эта ошибка уже вешала окно (FIXES «_on_knob_mode_change»). Проверять на показанном окне, не на `withdraw()`.
- Подсказка в режиме «Плавно»: действия этого режима (громкость, прокрутка, масштаб, яркость) уже работают в обе стороны. Режим «Влево / вправо» нужен для действий-нажатий.
- Проверки smoke: выбор `media.next_track` справа ставит `media.prev_track` слева и наоборот; действие без пары открывает замок; старый конфиг с несвязанными сторонами не переписывается. Нужные состояния тест создаёт сам во временной копии, от настроек владельца не зависит (FIXES «smoke_ui.py — проверка фейдера зависела от живого конфига»).

## 4. Скруглённые углы «срезаны» (лесенка)

Увеличенный снимок владельца: углы карточек нарисованы без сглаживания, ступеньками.
- Выяснить причину. Версия: CustomTkinter рисует углы шрифтом-фигурой (`DrawEngine.preferred_drawing_method = "font_shapes"`, файл `CustomTkinter_shapes_font.otf`). Если шрифт не загрузился, рисуются многоугольники без сглаживания.
  - Проверить в запуске из исходников и в exe: `--collect-data customtkinter` кладёт шрифт, но регистрируется ли он?
  - Проверить при масштабе 125%.
- Исправление — такое, чтобы углы были сглажены в обоих запусках. Если штатно не выходит — карточки фоном-картинкой (PIL, отрисовка с запасом по размеру и уменьшением), как у крутилок в п. 8.
- Отдельно проверить края окон без рамки (диалоги, меню, тост) — там `-transparentcolor` с цветом-ключом (`dialogs._key`). Каймы быть не должно в обеих темах.
  - Если кайма есть — готовое решение уже в проекте: скругление через `DwmSetWindowAttribute`, как в `mvave/volume_osd.py`. Там `-transparentcolor` отвергнут именно из-за каймы (FIXES «volume_osd.py»).
- Приёмка: увеличенные в 4 раза кадры углов карточки, кнопки, диалога — до и после, в обеих темах.

## 5. Индикатор банка — оставить, но сделать понятным

Ответ владельцу:
- Банки **переключаются**: кнопка PAD BANK на корпусе меняет диапазон нот пэдов, банков 8 (4 и 8 шлют одинаковые ноты).
- Программа узнаёт банк по пришедшей ноте. Номер нужен ей самой: адрес записи цвета на пэд зависит от банка.
- Назначения одинаковы во всех банках.

Сделать:
- Вместо оранжевой плашки «Банк 3» — нейтральная подпись «Pad bank 3».
- Рядом «Knob bank 1/2»: банк крутилок виден по CC — 30–37 первый, 38–45 второй (`KNOB_CC_MAP`).
  - Если крутилка привязана вручную к CC вне 30–45 (ручная привязка главнее карт), банк не определяется — подпись не менять.
- Подсказка при наведении объясняет всё вышесказанное.
- Цвет — `theme.MUTED`, без плашки.

## 6. Переключатель «Определить» — переименовать и объяснить

Что делает сейчас: пока включён, нажатие контрола на устройстве **выделяет** его в программе и **не выполняет** назначенное действие. Так удобно найти, где на схеме физическая кнопка.
- Переименовать в «Выбор нажатием».
- Подсказка при наведении: «Нажмите контрол на устройстве — он выделится справа, действие не выполнится».
- Раздел в справке (п. 7).

## 7. Имена элементов — латиницей; кнопка «i» со справкой

**Имена:**
- `PAD 6`, `KNOB 6`, у кнопок — `BUTTON` и значок кнопки.
- Везде, где имя видно: заголовок инспектора, строка последнего события в шапке (сейчас `KNOB_1 [CC30]: 24` → `KNOB 1 · CC 30 · 24`), баннер привязки, подписи.
- uid в конфиге (`pad_6`, `knob_6`, `btn_4`) **не меняются**.
- Транспортные кнопки (ответ владельца): порядок и смысл в программе верные — назад, вперёд, play, пауза, запись. Надписей нет, остаются значки. Назад / вперёд сейчас `◀ ▶` и путаются с play `▶` — заменить на MDL2 «предыдущий / следующий» (``, ``). Play, пауза, запись — тоже MDL2 (``, ``, ``), чтобы стиль был один.

**Кнопка «i»:**
- Кнопка-иконка (MDL2 `\uE946`) в шапке слева от «Настройки».
- Открывает окно справки — свой Modal, прокрутка, ширина около 560 px.
- Разделы по порядку:
  1. подключение и заряд;
  2. схема: что можно назначить, что серое и почему;
  3. назначение действия;
  4. крутилки: «Плавно», «Влево / вправо», замок;
  5. привязка MIDI («Привязать», «Забыть», «повесить сюда»);
  6. цвет пэдов, палитра, яркость пэда и общая яркость;
  7. пресеты, экспорт и импорт, перенос на другой ПК;
  8. тема;
  9. трей и автозапуск;
  10. «Выбор нажатием»;
  11. банки;
  12. если не работает: Ctrl+D — журнал, переподключение, «Отправить заново».
- Текст по-русски, короткими абзацами, без технических строк.
- Текст справки — в отдельном модуле `mvave/help_text.py`, не внутри вёрстки.

## 8. Крутилки: гладкая отрисовка

- Сейчас `UIKnob` рисует `tk.Canvas` без сглаживания — кольцо и корпус пиксельные, лесенкой.
- Главное требование владельца: кольцо **очень гладкое и ровное**, без ступенек на любом масштабе Windows.
- Рисовать через PIL с запасом ×4 и уменьшением (`LANCZOS`) в `ImageTk.PhotoImage`:
  - тело с лёгким объёмом;
  - кольцо — сплошная окружность-декор, ровной толщины;
  - указатель с точкой-акцентом.
- Кольцо **не** прогресс: без дуги, без упоров. Крутилка бесконечная, угол без пределов (FIXES «UIKnob — бесконечное вращение»). API `rotate(delta)` сохранить; кадр выбирается по `angle % 360`.
- Кэш кадров по (теме, углу с шагом 5°) — 72 кадра на тему. После смены темы (`rebuild_ui`) кадры берутся из кэша новой темы.
- Цвета — токены `KNOB_*` из темы.
- Размер прежний (48 px), раскладка схемы не меняется: она выверена, см. FIXES «пустое место на схеме».
- Декодер CC в `_handle_knob` не трогать (FIXES «CC декодер: АБСОЛЮТНЫЙ»).
- Колесо мыши над крутилкой — **не делать**, владелец отказался.
