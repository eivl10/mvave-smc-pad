## 2026-09-17 — mvave/protocol.py:read_response_data — разбор ответа на чтение

Что: Ответ устройства на команду чтения (`0x23`) — это полный вендорский фрейм, а не голые данные: заголовок (6 байт) + region/addr/count (8 байт) + данные + чексумма. Первая версия дымового скрипта скармливала `parse_state_block` весь фрейм целиком. Смещения поехали, и вместо ошибки вернулся правдоподобный мусор: `bank=5` вместо `bank=3`.
Логика: Добавлена `read_response_data(frame)` — проверяет префикс `00 59`, сверяет чексумму, сверяет объявленный `count` с фактической длиной данных и возвращает `frame[14:-1]`. Разбор состояния идёт только от неё.
Итог: На реальном ответе `00 59 23 18 … C6` блок состояния = `E1 00 3F 00 00 00 02 00 02 01 00 00 …`, отсюда slot=0, bank=3. Совпадает с независимым фактом: bank 3 — заводская карта с нотами 36-51, ровно то, что приложение видит на входе.

Почему это важнее, чем выглядит: запись в неправильный банк **не даёт никакой ошибки**. Устройство исправно отвечает ACK на каждый фрейм, а пэд не горит — картина неотличима от «протокол не работает». Ровно на этом уже один раз потеряли задачу (см. запись про Note On). Зафиксировано тестом `test_read_response_data_real_capture` на реальном захвате с железа, плюс тест явно проверяет, что разбор сырого фрейма даёт ДРУГОЙ результат — иначе тест не ловил бы саму ошибку.

## 2026-09-17 — цвет пэдов: почему Note On не работал

Что: Попытка зажечь пэд через MIDI Note On с velocity как индексом цвета не давала ничего. Задача была отложена как требующая USB-дампов.
Логика: У каждого пэда в его 26-байтовой записи есть байт `Led` на смещении +8. Заводское значение `0xFF` выводит пэд из-под управления хостом: показывается поле RGB записи, а Note On от хоста игнорируется молча. Цвет ставится не через MIDI-характеристику, а через отдельный вендорский GATT-канал `AE41`, который приложение вообще не открывало. Протокол взят из публичного реверс-инжиниринга, см. docs/PROTOCOL.md.
Итог: Подтверждено на железе 2026-09-17 — `AE40/AE41/AE42` присутствуют, MTU 512, чтение live-состояния отвечает, записи подтверждаются ACK. Выбран режим 24-битного RGB (unarmed), а не палитра по velocity: палитра вся пастельная, различимо около пяти цветов. Отвергнуто: Note On любого канала при `Led=0xFF`; SysEx через MIDI-характеристику (это USB-путь, по BLE фрейм идёт сырым в AE41).
